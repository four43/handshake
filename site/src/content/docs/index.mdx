<div class="hs-section not-content">
  <p class="hs-kicker">What it does</p>
  <h2 class="hs-h2">Everything before the first packet.</h2>
  <p class="hs-lede">Matchmaking, NAT traversal and flaky mobile sockets are the same chore in every multiplayer game. Handshake does them once, so your game starts at <code>peer.send()</code>.</p>
  <div class="hs-grid">
    <Feature title="Rooms in one code" art="A host with three guests, a fourth on the way" {...art.rooms}>
      Five-character join codes with no look-alike letters. Rooms can be private (code + key, QR-friendly) or public, and the lobby lists nearby rooms first.
    </Feature>
    <Feature title="Peer to peer" art="Two players exchanging data directly" {...art.p2p}>
      The server only relays connection setup. Game data flows host ↔ guest over WebRTC data channels and never touches it.
    </Feature>
    <Feature title="TURN when it must" art="Two players connected through a relay" {...art.turn}>
      A built-in TURN relay for players on cellular or strict Wi-Fi, and relay-only links to strangers so nobody learns anyone's IP.
    </Feature>
    <Feature title="Survives iPhones" art="A dropped player reconnecting to the host" {...art.resume}>
      Sockets drop all the time on phones. Members keep their seat for a grace period and resume automatically, with ICE restarts and a wake lock.
    </Feature>
    <Feature title="Two channels" art="A fast unreliable channel and a reliable one between two players" {...art.channels}>
      <code>state</code> is unordered with no resends, for snapshots. <code>events</code> is reliable and ordered, for joins, scores and chat.
    </Feature>
    <Feature title="Tiny and self-hosted" art="A signaling server introducing four players" {...art.tiny}>
      One Rust binary in a ~20 MB distroless image, plus a single dependency-free <code>handshake.js</code> that each game vendors.
    </Feature>
  </div>

<Tabs>
<TabItem label="Host">
```js
import { Handshake } from './handshake.js';

const hs = new Handshake({
  server: 'https://signal.example.com',
  app: 'pig-pens',
  version: 3,
  name: 'Seth',
});

const room = await hs.createRoom({ maxPlayers: 6 });
showQrCode(room.shareUrl); // ?r=<code>&k=<key>

room.on('peer', peer => {
  peer.send(snapshot);                  // unreliable, binary
  peer.send({ go: true }, { reliable: true });
  peer.on('message', data => applyInput(peer.id, data));
});
```
</TabItem>
<TabItem label="Guest">
```js
import { Handshake, HandshakeError } from './handshake.js';

const hs = new Handshake({ server, app: 'pig-pens', version: 3, name: 'Ada' });

try {
  const room = (await hs.joinFromUrl()) ?? (await hs.joinRoom(askForCode()));
  room.on('peer', host => {
    host.on('message', data => render(data));
    host.connectionType; // 'direct' | 'relayed'
  });
  room.on('closed', reason => backToLobby(reason));
} catch (e) {
  if (e instanceof HandshakeError && e.code === 'full') showFull();
}
```
</TabItem>

    <p class="hs-kicker">How it works</p>
    <h2 class="hs-h2">Introduce, then step aside.</h2>
    <div class="hs-steps">
<Steps>
1. Your game page gets a short-lived **session token** from `POST /session`. The server checks the page's origin against your app's allowlist.
2. The host **creates a room** over the WebSocket and gets a join code. Guests join with the code (and key, for private rooms).
3. The server **relays SDP and ICE** between the host and each guest until their data channels open, through TURN if needed.
4. From then on, **game traffic is peer to peer**. The socket stays open only for reconnects and room events.
</Steps>
